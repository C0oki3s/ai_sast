## On-demand context protocol

The supplied source window and Security IR context may not be enough to resolve every verification gate. Still return a full verdict this round using only supplied evidence — never assume, invent, or wait to answer. When a gate outcome depends on evidence not yet supplied (a symbol's own definition, its callers, its callees, a bounded call-flow neighborhood, a file's imports, or a route registration), name the smallest exact `context_requests` entries that would resolve it: symbol, containing path, and the exact line range already known, or the definition/callers/callees/flow/imports/route relationship needed. Request `flow` only for a concrete source-to-effect or control-ordering question that the existing slice cannot answer. Previously resolved requests are echoed back as `context_expansions`; do not repeat a request already answered there. Leave `context_requests` empty once the verdict no longer depends on undisclosed evidence. A request is a lead for the next round, not a delay tactic — it must not change this round's verdict, which must stand on the evidence already in hand.
