## On-demand context protocol

The supplied source window and Security IR context may not be enough to resolve every verification gate. Still return a full verdict this round using only supplied evidence — never assume, invent, or wait to answer. When a gate outcome depends on evidence not yet supplied (a symbol's own definition, its callers, its callees, a bounded call-flow neighborhood, a file's imports, a route registration, sibling routes in the same file, an ad-hoc repository search, or stored security knowledge), name the smallest exact `context_requests` entries that would resolve it: symbol, containing path, and the exact line range already known, or the definition/callers/callees/flow/imports/route/sibling_handlers/search/knowledge relationship needed. Request `flow` only for a concrete source-to-effect or control-ordering question that the existing slice cannot answer. Every `context_requests` entry must set every field (`path`, `symbol`, `start_line`, `end_line`, `offset`, `pattern`, `query`); leave the fields a given `kind` does not use at their empty default (`""` for strings, `1` for `start_line`/`end_line`, `0` for `offset`) rather than fabricating a value. Set `offset` to `0` unless you are paging through a previously truncated result. Previously resolved requests are echoed back as `context_expansions`; do not repeat a request already answered there. Leave `context_requests` empty once the verdict no longer depends on undisclosed evidence. A request is a lead for the next round, not a delay tactic — it must not change this round's verdict, which must stand on the evidence already in hand.

`callers`, `callees`, `route`, `sibling_handlers`, and `search` expansions are paginated: a resolved expansion carries `total`, `returned`, `offset`, and `truncated`. When `truncated` is true, the visible edges are not the full set — never treat a truncated page as exhaustive. Either request the next page with `offset` advanced by the page's `returned` count, or, if you stop paging, record the gap explicitly in `evidence_gaps` rather than silently reasoning as if no further callers, callees, routes, sibling handlers, or search matches exist.

`sibling_handlers` names a `path` and returns the other routes registered in that same file, excluding the one at `symbol` — use it to check whether a neighboring handler applies shared middleware, authorization, or validation that the candidate's own handler omits. `search` runs one ad-hoc repository-wide pattern match: set `pattern` to the exact literal or regex to search for, optionally set `path` to a glob that scopes the search to one area, and read back `matches` (path/line pairs only — follow up with a `window` request on a specific match to see its content). `knowledge` looks up `query` against the durable security-knowledge store already populated for this repository; it never performs new web research mid-review, so an empty result means nothing is stored yet, not that no relevant knowledge exists.
